# VisionGuard Machine Learning Model Research & Architecture Notes

This document provides a thorough research review of the upstream computer vision models evaluated for VisionGuard's automated printed circuit board (PCB) component inspection and defect classification pipeline.

---

## 1. ParsaVictor/pcb-component-detection-yolo26

- **Repository**: [https://huggingface.co/ParsaVictor/pcb-component-detection-yolo26](https://huggingface.co/ParsaVictor/pcb-component-detection-yolo26)
- **Dataset**: `ParsaVictor/pcb-component-detection` (>108,000 annotated component instances across hundreds of high-resolution boards)
- **Task**: **Component Localization & Fine-Grained Classification** (Does **NOT** detect defects)
- **License**: MIT License / Open Access with Academic Attribution
- **Architecture**: Ultralytics YOLO (PyTorch `.pt` weights) with high-resolution tiling strategy ($1024 \times 1024$ native crops with 25% overlap) to prevent 0402 / 0603 tiny SMT parts from vanishing.

### Key Weights in Repository
1. `any_best.pt` (Locator): Single-class ("component") locator trained to find all component geometries regardless of identity.
2. `fine_best.pt` (Typer): 13-class fine-grained detector initialized from locator weights for precise component categorization.
3. `tree_rf.joblib` & `tree_rf_boards.joblib`: Random Forest classifiers with 33 engineered computer vision features for edge ambiguity resolution.

### Class List (13 Fine-Grained Classes)
1. `Resistor`
2. `Capacitor`
3. `IC` (Integrated Circuit)
4. `Electrolytic Capacitor`
5. `Transistor`
6. `Diode`
7. `Inductor`
8. `Connector`
9. `Marker`
10. `Other`
11. `LED`
12. `Switch/Button`
13. `Oscillator`

### Loading & Inference Method
Loaded via standard `ultralytics.YOLO` in PyTorch:
```python
from huggingface_hub import hf_hub_download
from ultralytics import YOLO

weights_path = hf_hub_download(
    repo_id="ParsaVictor/pcb-component-detection-yolo26",
    filename="fine_best.pt",
    cache_dir="backend/models/cache"
)
model = YOLO(weights_path)
results = model.predict(source=image, imgsz=1024, conf=0.25)
```

### Metrics & Performance
- Standard mAP@0.5 exceeds 84% on fine-grained classes when evaluated at native resolution.
- Tiled inference preserves small footprint aspect ratios (0402, SOT-23, QFN pads).

## 2. SanderGi/PCB-Detection

- **Repository**: [https://github.com/SanderGi/PCB-Detection](https://github.com/SanderGi/PCB-Detection)
- **Hugging Face Hub**: `SanderGi/PCB-SEG` and `SanderGi/PCB-OBB`
- **Task**: **Macro PCB Localization, Segmentation & Oriented Bounding Box (OBB)**
- **Does it detect defects?**: **NO.** The SanderGi repository explicitly detects **if and where a PCB itself exists** in a scene (macro bounding box and polygon segmentation mask). It does not classify micro soldering defects (solder bridges, icicles, voids, or tombstoning).
- **License**: MIT License
- **Classes**:
  - `PCB` (single class: board surface / perimeter)
- **Weights**:
  - `pcb-seg.pt` (6.4 MB): Segmentation model achieving 99.8% F1 score for board isolation.
  - `pcb-obb.pt` (2.6 MB): Oriented bounding box model with 93.8% F1 score.

### Loading & Inference Method
```python
from ultralytics import YOLO

# Downloaded from SanderGi releases / HuggingFace
pcb_locator = YOLO("backend/models/pcb-seg.pt")
results = pcb_locator.predict(source=image, task="segment")
```

## 3. Defect Analysis Strategy (Per Project Requirements)

Because `SanderGi/PCB-Detection` detects board segmentation rather than soldering defects, VisionGuard adopts the sanctioned hybrid defect engine:
1. **Classical Computer Vision Heuristics (OpenCV)**:
   - **Solder Bridge Detection**: Adaptive thresholding and morphological skeleton analysis on pin header gaps (e.g. ICSP clusters) to flag conductive shorts between adjacent pins.
   - **Component Discoloration / Scorching**: HSV color space masks identifying localized darkening or copper burning around power regulators.
   - **Missing Component Voids**: Edge contour density checks inside predicted footprints (e.g., bare solder pads with flux residue).
   - **Bent Header Pins**: Contour orientation and angle deflection checks along linear pin arrays.
2. **Provenance Transparency**:
   - Defect detections generated by heuristic algorithms are explicitly stamped with `source: "heuristic"`.
   - Any machine-learning-derived bounding boxes retain `source: "model"`.
   - Never label heuristic findings as model detections.

## 4. Hardware Acceleration & Device Dispatch

- The backend automatically checks `torch.cuda.is_available()`.
- If an NVIDIA GPU / CUDA runtime is present, models are dispatched to `"cuda"`.
- Otherwise, models gracefully execute on `"cpu"` using multi-threaded PyTorch primitives with quantized INT8 / FP16 optimizations where appropriate.
- Device state and inference latency are reported live through `GET /api/models` and `GET /api/health`.
